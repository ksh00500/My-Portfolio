# 번역 원칙 (한국어 → 영어)

2026-10-30 소유자 결정. DB v2의 `*_ko` / `*_en` 칸에 적용한다.

## 역할

- **원문은 한국어이고 소유자가 쓴다.** `*_ko`가 단일 원본이다.
- **영어는 Claude가 번역하고 소유자가 확인한다.** 확인 전 번역은 DB에 넣지 않는다.
- 영어 칸이 비어 있으면 사이트는 한국어를 대신 보여준다. 급하지 않은 항목은 비워 둬도 된다.

## 번역 방식

- 단어가 아니라 **의도를 옮긴다.** 직역보다 영어권 채용 담당자가 자연스럽게 읽는 문장을 우선한다. 단, 사실(숫자·기간·역할 범위·성과)은 더하거나 부풀리지 않는다.
- 프로젝트명·서비스명·브랜드명은 **그대로 둔다** (SENRO, KeyDa, FRESK 등).
- 기관·대회·프로그램은 **공식 영문 명칭이 확인될 때만** 쓴다. 확인되지 않으면 묻는다.
- 같은 용어는 항상 같은 영어로 쓴다. 정해진 용어는 아래 「용어집」에 기록한다.

## 모르면 묻는다 — 유추 금지

다음 경우에는 추측해서 번역하지 않고, 그 항목의 영어 칸을 비운 채 **질문 목록**으로 묶어 소유자에게 묻는다.

- 문장의 의도나 강조점이 두 가지 이상으로 읽힐 때 (예: 비유, 슬로건, 줄임말)
- 역할·기여 범위가 모호할 때 (예: "참여"가 개발인지 기획인지)
- 기관·직함·상 이름의 공식 영문 표기를 확인할 수 없을 때
- 한국 특유의 제도·용어라 영어권 독자에게 설명이 필요할 수 있을 때 (예: 학기제, 장학 제도명)
- 원문에 오타나 사실 충돌이 의심될 때 (고치지 않고 묻는다)

## 작업 순서

1. 번역 대상 한국어를 모은다(공개 데이터는 `/api/portfolio`, 비공개 칸은 소유자 제공).
2. 검토표를 만든다: `한국어 | 영어 초안 | 질문(있으면)`. 질문이 있는 행은 영어 칸을 비운다.
3. 소유자가 확인·수정하고 질문에 답한다. 답은 용어집에 기록해 다시 묻지 않는다.
4. 확인된 행만 DB에 넣는다. DB 쓰기는 `db/BACKUP_WORKFLOW.md` 절차(사전 백업)를 따른다.

## 용어집

소유자 답변으로 확정된 표기를 여기에 쌓는다.
